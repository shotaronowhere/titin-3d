## Export contract

The pure `researchExport({ model, presentationState, selection, buildIdentity, inputManifest })`
serializer emits deterministic UTF-8/LF bytes for:

- `titin-state.json` (`titin-state-export/1`), ordered
  `schema, build, state, mechanics, reproduction`;
- `claim-support.json` (`titin-claim-support-export/1`), ordered
  `schema, build, context, claims, references`;
- `force-curve.csv` with columns
  `sarcomere_length_nm,force_pN_min,force_pN_central,force_pN_max,status,reason,parameter_set_id,model_fingerprint,app_revision,build_inputs_fingerprint,export_contract_fingerprint`;
- `regional-extension.csv` with columns
  `sarcomere_length_nm,region_id,extension_nm,added_length_nm,incremental_compliance_share,status,parameter_set_id,model_fingerprint,app_revision,build_inputs_fingerprint,export_contract_fingerprint`;
- one canonical URL-v2 deep link whose story step, confidence state, named
  scene/selection, or complete Custom camera/scale/context/layer state must match the
  exported state exactly.

JSON Schemas are shipped in `release/export/`. The validator applies those checked-in
schemas, exact root/nested key order, strict RFC 4180 CSV shape and escaping, row and
direct-model parity, exact contextual source closure, candidate-authenticated pinned
inputs, canonical deep-link restoration, and omission semantics. Caller-provided claim
IDs and candidate identities cannot override canonical state. The serializer has no
clock, randomness, locale formatting,
DOM/network/file reads, generated-payload checksum, or artifact self-checksum.
